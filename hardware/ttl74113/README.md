# Стенд Arduino Nano и 74HC113

Временная проверка физической микросхемы. Перед merge request этот каталог удаляется.

Цоколёвка — ST M74HC113, DIP-14. Вывод 7 это GND, вывод 14 это VCC. У каждой половины свой такт, J, K и активный низкий `nPR`. Входа сброса нет. Такт срабатывает по спаду `CK`: пока `nPR` высокий, `J=0 K=0` хранит состояние, `J=1 K=0` пишет 1, `J=0 K=1` пишет 0, `J=1 K=1` переключает. Низкий `nPR` асинхронно ставит `Q=1` и `nQ=0` и перекрывает такт. Выходы двухтактные, подтяжки не нужны. Та же цоколёвка у SN74LS113A; стенд не подходит для 74HC112, у той 16 выводов и земля на выводе 8. Перед подачей питания сверить маркировку и убедиться, что вывод 7 соединён с GND.

Nano работает от 5 В. D0 и D1 заняты Serial (115200) и к микросхеме не подключаются. D6, D11 и D13 не используются. Между выводами 14 и 7, рядом с корпусом, поставить конденсатор 100 нФ. До старта проверки скетч держит оба `nPR` высокими, оба такта высокими и J/K низкими. Состояние после включения даташит не задаёт, поэтому известный 0 набирается так: сначала `nPR`, затем запись 0 по спаду.

Точка или выемка на корпусе отмечает сторону вывода 1. Ниже нумерация DIP-14 сверху, от выемки вниз по левому ряду и вверх по правому.

| Вывод 74HC113 | Сигнал | Куда на Nano | Направление |
| --- | --- | --- | --- |
| 14 | VCC | 5V | питание |
| 7 | GND | GND | питание |
| 1 | 1CK | D2 | выход Nano |
| 2 | 1K | D3 | выход Nano |
| 3 | 1J | D4 | выход Nano |
| 4 | 1nPR | D5 | выход Nano |
| 5 | 1Q | D12 | вход Nano |
| 6 | 1nQ | A0 | вход Nano |
| 8 | 2nQ | A1 | вход Nano |
| 9 | 2Q | A2 | вход Nano |
| 10 | 2nPR | D10 | выход Nano |
| 11 | 2J | D9 | выход Nano |
| 12 | 2K | D8 | выход Nano |
| 13 | 2CK | D7 | выход Nano |

Скетч `ttl74113_nano/ttl74113_nano.ino` после сброса ждёт любой символ из Serial Monitor и проверяет обе половины. Для каждой: запись 0, установка без такта и поверх спада, который писал бы 0, удержание после отпускания `nPR`, затем JK по спаду: хранение, запись 1, запись 0 и два переключения. Фронт такта и смена J/K при низком такте состояние не меняют. Пока проверяется одна половина, вторая остаётся в записанном нуле. Успех — последняя строка `RESULT PASS`. Первое расхождение печатается как `RESULT FAIL` и дальше не затирается.
