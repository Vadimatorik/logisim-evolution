# Стенд Arduino Nano и 74HC4017

Временная проверка физической микросхемы. Перед merge request этот каталог удаляется.

Цоколёвка — Nexperia 74HC4017 и TI CD74HC4017. У DIP-16, SO16 и TSSOP16 номера выводов совпадают: вывод 8 это GND, вывод 16 это VCC. Если корпус не DIP, для макетной платы нужен переходник. Перед подачей питания сверить маркировку и убедиться, что вывод 8 соединён с GND.

Nano работает от 5 В. D0 и D1 заняты Serial (115200) и к микросхеме не подключаются. A6 и A7 у ATmega328P только аналоговые, как цифровые их использовать нельзя. Между выводами 16 и 8, рядом с корпусом, поставить конденсатор 100 нФ. Входы CMOS нельзя оставлять висящими: CP0, CP1 и MR приходят с Nano. Выходы всегда активны, последовательные резисторы не нужны.

Точка или выемка на корпусе отмечает сторону вывода 1. Ниже нумерация сверху, от выемки вниз по левому ряду и вверх по правому.

- Вывод 1, Q5 — D10, вход Nano
- Вывод 2, Q1 — D6, вход Nano
- Вывод 3, Q0 — D5, вход Nano
- Вывод 4, Q2 — D7, вход Nano
- Вывод 5, Q6 — D11, вход Nano
- Вывод 6, Q7 — D12, вход Nano
- Вывод 7, Q3 — D8, вход Nano
- Вывод 8, GND — GND Nano, питание
- Вывод 9, Q8 — D13, вход Nano
- Вывод 10, Q4 — D9, вход Nano
- Вывод 11, Q9 — A0, вход Nano
- Вывод 12, Q5-9 — A1, вход Nano
- Вывод 13, CP1 — D2, выход Nano
- Вывод 14, CP0 — D3, выход Nano
- Вывод 15, MR — D4, выход Nano
- Вывод 16, VCC — 5V Nano, питание

D13 подключён к Q8, поэтому светодиод платы загорается, когда декодированный выход 8 в HIGH.

Высокий MR сбрасывает счётчик в 0: Q0 и Q5-9 в HIGH, Q1–Q9 в LOW. При низком MR фронт CP0 сдвигает счётчик, только если CP1 в LOW. Спад CP1 сдвигает счётчик, только если CP0 в HIGH. Q5-9 в HIGH на шагах 0–4 и в LOW на шагах 5–9.

Скетч `ttl744017_nano/ttl744017_nano.ino` после сброса ждёт любой символ из Serial Monitor. Он проверяет удержание при высоком MR, десять шагов по фронту CP0 при низком CP1 вместе с переходом 9→0, отсутствие шага по спаду CP0 и при высоком CP1, шаг по спаду CP1 при высоком CP0 и отсутствие шага при низком CP0. Успех — последняя строка `RESULT PASS`. Первое расхождение печатается как `RESULT FAIL` и дальше не затирается. Повторный символ запускает проверку ещё раз.
