# Стенд Arduino Nano и 74HC40103

Временная проверка физической микросхемы. Перед merge request этот каталог удаляется.

Цоколёвка — Nexperia 74HC40103 Rev. 6, 26 марта 2024. Это не CD40103: у серии 4000 другие выводы и спад такта. Вывод 8 это GND, вывод 16 это VCC. `MR` — асинхронный сброс в 255, активный низкий. `PL` — асинхронная загрузка `P7…P0`, тоже активный низкий; она важнее такта, но слабее `MR`. `PE` — синхронная загрузка по фронту `CP`, активный низкий, и она не смотрит на `TE`. Счёт идёт по фронту `CP`, когда `MR`, `PL` и `PE` высокие, а `TE` низкий. С 0 счётчик переходит на 255. `TC` активный низкий и без ожидания такта: он низкий только при коде 0 и низком `TE`. Выход двухтактный, резистор на `TC` не нужен.

В даташите Rev. 6 указаны корпуса SO16 и TSSOP16. Если придёт такой корпус, нужен переходник на макетную плату. Старый DIP-16 `74HC40103N` имеет те же номера выводов. Перед подачей питания сверить маркировку и убедиться, что вывод 8 соединён с GND.

Nano работает от 5 В. D0 и D1 заняты Serial (115200) и к микросхеме не подключаются. A6 и A7 у ATmega328P только аналоговые, как цифровые их использовать нельзя. Между выводами 16 и 8, рядом с корпусом, поставить конденсатор 100 нФ. До старта проверки скетч держит `MR` низким, поэтому код уже 255, `CP` низким, `PL` и `PE` высокими, `TE` высоким.

Внутренний код на выводы не выведен. Скетч судит о нём по `TC`: известный пресет N и N фронтов при низком `TE` обязаны дать низкий `TC`, следующий фронт — высокий.

Точка или выемка на корпусе отмечает сторону вывода 1. Ниже нумерация сверху, от выемки вниз по левому ряду и вверх по правому.

| 16 | VCC | 5V | питание |
| 8 | GND | GND | питание |
| 1 | CP | D2 | выход Nano |
| 2 | MR | D3 | выход Nano |
| 3 | TE | D4 | выход Nano |
| 4 | P0 | D5 | выход Nano |
| 5 | P1 | D6 | выход Nano |
| 6 | P2 | D7 | выход Nano |
| 7 | P3 | D8 | выход Nano |
| 9 | PL | D9 | выход Nano |
| 10 | P4 | D10 | выход Nano |

| 15 | PE | A1 | выход Nano |

Скетч `ttl7440103_nano/ttl7440103_nano.ino` после сброса ждёт любой символ из Serial Monitor. Он проверяет, что низкий `MR` важнее низкого `PL` даже при нуле на входах `P` и низком `TE`, асинхронный ноль без такта, подъём `TC` высоким `TE`, синхронный ноль только по фронту, длины 1, 2, 7, 8, 15, 16, 127, 128, 254 и 255, удержание при высоком `TE`, загрузку по `PE` при высоком `TE`, спад такта и 255 тактов после `MR`. Успех — последняя строка `RESULT PASS`. Первое расхождение печатается как `RESULT FAIL` и дальше не затирается.
